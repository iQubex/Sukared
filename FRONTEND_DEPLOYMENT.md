# Luavex Frontend Deployment

The frontend is a History API single-page application. Every browser route must serve `index.html` while static assets keep their normal paths.

The primary production frontend origin is `https://luavex.pntr.dev`. The
previous `https://sukared.onrender.com` site may remain online temporarily;
the backend admits it only as an exact credentialed-CORS migration fallback.

For a Render Static Site:

- Publish directory: repository frontend root
- Add these rules in **Redirects/Rewrites**, in this exact order:
  1. Rewrite `/auth/*` to `https://backend-luavex.up.railway.app/auth/*`
  2. Rewrite `/api/*` to `https://backend-luavex.up.railway.app/*`
  3. Rewrite `/*` to `/index.html`
- Keep the backend as a separate web service
- Do not proxy `/v2/g/:handle`; runtime-gate traffic continues to use the
  Railway origin generated by the protected client.

Render Static Site routing is configured in its Dashboard; this repository is
not Blueprint-managed. The `/auth/*` and `/api/*` rules must remain above the
SPA fallback. They are rewrites, not redirects: the browser-visible origin stays
`https://luavex.pntr.dev`. The Node frontend service implements the same route
mapping for local integration tests and web-service deployments.

Before switching OAuth in production, add this exact Discord redirect URI:
`https://luavex.pntr.dev/auth/discord/callback`. After the proxy rules are live
and verified, set Railway `DISCORD_REDIRECT_URI` to that same value. Keep
`FRONTEND_ORIGIN=https://luavex.pntr.dev`.

For local development run:

```powershell
node frontend-server.js
```

The local server provides SPA fallback for `/dashboard`, `/history`, `/changelog`, `/credits`, and `/settings`. It honors `PORT` and binds to `HOST` (default `0.0.0.0`).
